# ESP32 IoT Control Center --- V3

## 1. Objetivo

A V3 evolui o painel web local do ESP32, preservando o funcionamento
independente de roteador e Internet. O ESP32 cria sua própria rede Wi-Fi
e hospeda a interface de monitoramento e controle.

Esta versão mantém os sensores e o circuito da V2, melhora a
apresentação dos dados, sinaliza falhas de comunicação no navegador e
trata leituras inválidas do DHT22 sem enviar `NaN` como JSON.

## 2. Funcionalidades

-   Ponto de acesso Wi-Fi criado pelo ESP32.
-   Painel web adaptável a telas menores.
-   Exibição de temperatura e umidade do DHT22.
-   Exibição da leitura analógica do potenciômetro e de uma barra
    percentual.
-   Controle do LED pelo GPIO 2.
-   Atualização automática do painel a cada 2,5 segundos.
-   Indicador de estado da conexão HTTP.
-   Resposta JSON com `null` quando o DHT22 não fornece uma leitura
    numérica válida.
-   Resposta HTTP 404 para rotas desconhecidas.
-   Cabeçalho `Cache-Control: no-store` nas respostas dinâmicas para
    evitar dados em cache.

## 3. Hardware e ligações

  Componente                                    Ligação no ESP32
  --------------------------------------------- ------------------
  LED (com resistor em série de 220--330 Ω)     GPIO 2
  DHT22 --- VCC                                 3V3
  DHT22 --- DATA                                GPIO 4
  DHT22 --- GND                                 GND
  Potenciômetro --- terminal central (cursor)   GPIO 34
  Potenciômetro --- terminal externo            3V3
  Potenciômetro --- outro terminal externo      GND

**Importante:** - Confira o pinout do seu módulo DHT22. Em um sensor
DHT22 de quatro pinos sem placa adaptadora, pode ser necessário um
resistor pull-up de 4,7--10 kΩ entre DATA e 3V3. - Nunca aplique 5 V
diretamente a um pino GPIO do ESP32. - GPIO 34 é somente entrada e é
apropriado para a leitura analógica no ESP32 clássico. Outros modelos
ESP32 podem ter pinagens diferentes. - O LED integrado pode variar entre
placas; confirme se a sua placa realmente utiliza GPIO 2 para o LED.

## 4. Software necessário

-   Arduino IDE.
-   Pacote de placas ESP32 instalado na Arduino IDE.
-   Biblioteca **DHT sensor library** da Adafruit.
-   Biblioteca **Adafruit Unified Sensor**, caso solicitada como
    dependência.

Não é necessária uma biblioteca adicional de JSON: a resposta é montada
pelo próprio firmware.

## 5. Rede e acesso

O firmware cria um ponto de acesso com estes dados:

-   **SSID:** `ESP32-IOT`
-   **Senha:** `12345678`
-   **Endereço do painel:** `http://192.168.4.1`

Conecte o computador ou celular à rede do ESP32 e abra o endereço no
navegador. Não é necessário conectar o ESP32 a um roteador nem à
Internet.

A senha acima é adequada apenas para este projeto de laboratório. Para
uma implantação real, use uma senha exclusiva e mais forte.

## 6. Rotas HTTP

  Método                Rota        Função
  --------------------- ----------- -------------------------------------------------
  `GET`                 `/`         Entrega a página HTML
  `GET`                 `/data`     Retorna as leituras e o estado do LED em JSON
  `POST`                `/toggle`   Alterna o estado do LED e devolve o novo estado
  Qualquer outra rota   ---         Retorna HTTP 404

Exemplo de resposta de `GET /data`:

``` json
{
  "led": false,
  "temperature": 24.5,
  "humidity": 51.2,
  "pot": 2048
}
```

Os números acima são ilustrativos. Se uma leitura do DHT22 falhar, o
campo correspondente pode ser `null`, por exemplo `"temperature": null`.

## 7. Como funciona a atualização

1.  O navegador carrega a página em `/`.
2.  O JavaScript faz uma solicitação `GET /data`.
3.  O ESP32 retorna os valores em JSON.
4.  A página atualiza os indicadores sem recarregar todo o documento.
5.  O navegador repete a consulta a cada 2,5 segundos.
6.  Ao clicar no botão do LED, o navegador envia `POST /toggle` e depois
    consulta novamente os dados.

O firmware também respeita um intervalo mínimo de 2,5 segundos entre
leituras do DHT22. A leitura do potenciômetro é atualizada nas chamadas
de serviço do firmware.

## 8. Como gravar o firmware

1.  Abra `firmware/V3/ESP32_IoT_V3.ino` na Arduino IDE.
2.  Selecione a placa ESP32 correta e a porta serial.
3.  Confirme que as bibliotecas do DHT22 estão instaladas.
4.  Compile e carregue o programa.
5.  Abra o Monitor Serial em **115200 baud**.
6.  Conecte seu computador ou celular à rede `ESP32-IOT`.
7.  Acesse `http://192.168.4.1`.

## 10. Conceitos praticados

-   Ponto de acesso Wi-Fi (`WiFi.softAP`).
-   Servidor HTTP e rotas com `WebServer`.
-   Métodos HTTP GET e POST.
-   JSON e representação de valores indisponíveis com `null`.
-   Leitura analógica com `analogRead`.
-   Controle digital de saída com `digitalWrite`.
-   Atualização assíncrona da interface com `fetch`.
-   Tratamento de falhas de comunicação no navegador.
-   Uso de `millis()` para agendar leituras sem `delay()` no laço
    principal.

## 11. Limitações conhecidas

-   `WebServer` é um servidor síncrono simples, adequado a este projeto
    didático, mas não a todas as necessidades industriais.
-   O LED usa lógica ativa em nível alto; algumas placas podem exigir
    lógica diferente.
-   O intervalo de consulta do navegador e o intervalo de leitura do
    DHT22 são configurados separadamente, embora ambos estejam definidos
    em 2,5 segundos neste firmware.
-   A leitura do DHT22 pode falhar por ligação, alimentação,
    temporização ou defeito do sensor.
-   O valor percentual do potenciômetro é uma escala aproximada
    calculada a partir da leitura ADC de 0 a 4095; não representa uma
    grandeza física calibrada.
